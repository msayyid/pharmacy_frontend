## [0.8.0] - 2026-05-04

### Added

- Phase 8 — `lib/cart/queries.ts` — `useCart()` + `cartQueryKey`. Throws `ApiError` on missing data so consumers branch on `error` to render `ErrorState` (not `EmptyState`). Per CLAUDE.md OP-13 + Phase 8 plan D1: cart fetchers are mutation paths and MUST throw loudly. The catch-and-empty pattern from Phase 6/7 catalog fetchers is **forbidden** for cart surfaces. `staleTime: 0` (cart is hot data); `refetchOnWindowFocus: true` (multi-tab edit awareness).
- Phase 8 — `lib/cart/mutations.ts` — `useAddToCart`, `useUpdateCartItem` (optimistic + rollback), `useRemoveCartItem` (optimistic + rollback), `useClearCart`. Mutation queue per item ID via `mutationKey` serializes rapid PATCH dispatches. Add-to-cart is non-optimistic per plan D3; qty + remove are optimistic with rollback-on-error.
- Phase 8 — `lib/cart/store.ts` — Zustand UI store with `isDrawerOpen` + `lastAddedItemId`. Cart DATA stays in TanStack Query cache; this store is for narrow client-only UI hints per FRONTEND §11.2.
- Phase 8 — `components/cart/QuantityStepper.tsx` — DESIGN §13.6 with the critical Phase 8 plan D4 contract: rapid +/- clicks COLLAPSE into a single `onChange` dispatch after a 200ms debounce, NOT one PATCH per click. Local state advances optimistically through each click; one `onChange` fires after the LAST click + debounce window. The mutation queue per item ID handles the cross-pause case. Decrement disabled at min (default 1); increment disabled at max (max_per_order, when surfaced).
- Phase 8 — `components/cart/CartLine.tsx` — DESIGN §12.7 line item with thumbnail (or brand-pill via ProductImage), name (linked to PDP), snapshot price + line total, QuantityStepper, Remove. Two conditional banners above the line: red OOS banner with "Удалить" CTA when `is_in_stock=false` (per plan D5); yellow price-changed strip with "Обновить цену" CTA when `current_price !== price_snapshot` (per plan D6). Nullable-field handling: null `is_in_stock` → treat as in-stock; null `product_name` → `t("product.unavailable")`; null `current_price` → no price-change diff possible.
- Phase 8 — `components/cart/CartTotals.tsx` (RSC) — sticky totals card. Subtotal always visible; discount when > 0; delivery + total only when non-null (null pre-quote, populated at checkout in Phase 9); free-delivery progress strip when `free_delivery_remaining > 0`.
- Phase 8 — `components/cart/CartDrawer.tsx` (client) — Sheet from right. Globally mounted in `app/[locale]/layout.tsx`. Auto-closes on route change. Renders four states (loading skeleton / error+retry / empty+CTA / populated list+totals+checkout-CTA). Drawer footer's CTA links to `/cart` where checkout flows continue (Phase 9). Drawer is desktop-only — mobile users navigate to `/cart` directly via the cart icon's Link branch.
- Phase 8 — `components/layout/CartIconWithBadge.tsx` — replaces the Phase 6 stub cart icons. Renders mobile `<Link href="/cart">` + desktop `<button>`-trigger-drawer as siblings via Tailwind responsive classes. Badge counts DISTINCT line items (`cart.items.length`) per plan D8 — matches Apteka.ru / Wildberries convention. Hidden when count is 0; "99+" past 99.
- Phase 8 — `components/product/AddToCartButton.tsx` (client) — shared CTA for ProductCard + PDP. Disabled when `isInStock=false`; otherwise dispatches `useAddToCart` and surfaces a Sonner toast on success ("Добавлено в корзину" + "Перейти в корзину" action that opens the drawer) or a localized error toast on failure (`t(\`error.\${code}\`)`with`error.generic` fallback).
- Phase 8 — Sonner Toaster mounted in `app/providers.tsx` (position top-right, richColors, closeButton). Sonner was installed in Phase 2 but never rendered until now.
- Phase 8 — `app/[locale]/cart/page.tsx` — replaces the Phase 6 placeholder. Full-page cart with the four render branches; two-column desktop grid (lines + aside totals/checkout-CTA); single-column stack on mobile. Inline `CartTotalsClient` component (mirrors RSC `CartTotals`) because the page is a Client Component.
- Phase 8 — `app/[locale]/auth/otp/page.tsx` — wires the locked merge sequence per plan Q5 with an explicit "ORDER MATTERS — do not refactor without reading DECISION_LOG D12" comment. Six numbered steps: verify OTP → snapshot guest cart (fresh `GET /cart` — NOT cache; covers multi-tab case) → set tokens → mergeGuestCartIntoUser → invalidateQueries(cartQueryKey) → router.replace(returnUrl). Step 5 invalidates BEFORE step 6 redirects so `/cart` renders the merged cart immediately on landing — no "empty cart flash" per R-C mitigation.
- Phase 8 — Header swaps the inline cart Link for `<CartIconWithBadge>`. Header itself stays an RSC; CartIconWithBadge is the third client island after MobileMenu and SearchInput.
- Phase 8 — ProductCard CTA (Phase 6 disabled) and PDP CTA (Phase 7 disabled) both wire to `<AddToCartButton>`. Local `stockLabel` / `ctaDisabled` vars dropped from both.
- Phase 8 — 11 new i18n keys across all three locales (133 × 3, was 123 × 3): `cart.added`, `cart.checkout_cta`, `cart.go_to_cart`, `cart.line.{remove, update_qty, price_changed_action}`, `cart.merge_partial_failure` (plural form), `error.{cart_item_not_found, max_per_order_exceeded, product_not_found}`.

## [0.5.0] - 2026-05-03

### Added

- Phase 5 — Auth route handlers under `app/api/auth/`: `set-tokens` (POST receives the access+refresh pair from the OTP-verify response, sets `nookat_refresh` HttpOnly + Secure-in-prod + SameSite=Lax cookie at our origin), `refresh-tokens` (POST reads the cookie, calls backend `POST /api/v1/auth/refresh`, rotates the cookie, returns the new access token + expires_in), `logout` (POST best-effort backend logout, deletes the cookie, 204). Refresh token never enters JS; access token never enters storage.
